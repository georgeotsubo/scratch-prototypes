# Playlist Design System — tokens for prototypes

CSS custom properties generated from the **Playlist Design System** Figma file
(`VMrMBZC3y8lOfxic25V7HT`). Use these instead of hard-coded colors, type, spacing,
radius and shadows in `prototype-N/`.

> **Serving locally?** `vercel dev` snapshots the file list at startup, so any file
> added since it launched 404s until you restart it — which shows up as missing icons,
> unstyled components, or an empty token list. Restart `vercel dev` after adding files
> here. Opening `index.html` straight off disk always works.

**Open [index.html](index.html) in a browser** — it's the whole design system on one
page: every colour, text style, spacing/radius/elevation token, and every component,
with a sidebar, a filter box, and a light/dark toggle. It's also linked from the repo
landing page under "Design system".

## Files

| File | What it is |
| --- | --- |
| `tokens.css` | **Link this first.** 560 custom properties, light + dark. |
| `typography.css` | **Link this second.** 67 text style classes. Needs `tokens.css`. |
| `components.css` | **Link this third.** Buttons, chip, fields, cards, banner, tab bar, icons. |
| `icons.js` | 30-icon SVG sprite, injected on load. Generated by `build-icons.mjs` from `icons/`. Include wherever you use `.pl-icon`. |
| `tokens.js` / `typography.js` | Same data as JS globals — only used by `index.html`. |
| `tokens.raw.css` | Untouched export from Figma. Kept for diffing; don't link it. |
| `postprocess-tokens.mjs` | Turns `tokens.raw.css` into `tokens.css` + `tokens.js`. |
| `build-typography.mjs` | Generates `typography.css` from `tokens.css`. |
| `index.html` | **The browsable design system** — foundations, text styles, components, parity table. |

## Using it in a prototype

```html
<link rel="stylesheet" href="../design-system/tokens.css">
<link rel="stylesheet" href="../design-system/typography.css">
<link rel="stylesheet" href="../design-system/components.css">
<link rel="stylesheet" href="prototype.css">
<script src="../design-system/icons.js"></script>
```

DM Sans still needs loading separately — the tokens name the family, they don't ship it:

```html
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:opsz,wght@9..40,100..1000&display=swap" rel="stylesheet">
```

Then:

```css
.class-card {
  background: var(--pl-surface-default);
  color: var(--pl-text-primary);
  border: 1px solid var(--pl-border-subtle);
  border-radius: var(--pl-radius-component-card-default);
  padding: var(--pl-card-padding-md);
  gap: var(--pl-card-gap);
  box-shadow: var(--pl-elevation-sm);
  font-size: var(--pl-body-md-regular-size);
  line-height: var(--pl-body-md-regular-lineheight);
  font-weight: var(--pl-body-md-regular-weight);
}
```

Dark mode is opt-in via an attribute, and works on any subtree — not just `<html>`:

```html
<html data-theme="dark">        <!-- whole prototype -->
<div data-theme="dark">…</div>  <!-- one sheet / one section -->
```

## Text styles

Don't apply the four typography tokens by hand — use a class from `typography.css`.

There are two layers, because Figma has two. **Reach for the role styles.**

**Role styles (29)** — the actual Figma *text styles*, the layer designers apply.
Class name mirrors the Figma name:

| Class | Figma text style | |
| --- | --- | --- |
| `.pl-page-title` | `role/pageTitle` | 32/40 · primary title in a view |
| `.pl-content-title` | `role/contentTitle` | 24/28 · primary title within a page or view |
| `.pl-section-header` | `role/sectionHeader` | 20/28 · section divider |
| `.pl-card-title` | `role/cardTitle` | 18/26 · title in cards, tiles, list items |
| `.pl-list-title` | `role/listTitle` | 16/24 · list rows, large CTA buttons |
| `.pl-tab-label` | `role/tabLabel` | 12/16 |
| `.pl-caption-primary{,-medium,-bold}` | `role/captionPrimary …` | 12/16 · metadata |
| `.pl-caption-secondary` | `role/captionSecondary` | 11/14 · lowest priority |
| `.pl-body-{large,medium,small}-{regular,medium,semibold}` | `role/body/…` | 16/24, 14/20, 13/18 |
| `.pl-button-label-{large,medium,small}-{medium,semibold}` | `role/button label/…` | 16/24, 14/20, 13/18 |
| `.pl-input-label-{large,medium}-{medium,semibold}` | `role/input label/…` | 16/24, 14/20 |

**Token styles (39)** — `.pl-text-{style}`, one per Typography/Semantic variable
(`.pl-text-title-md-semibold`, `.pl-text-display-xl`, …). Use these only when no role
style fits; roughly half have no role style pointing at them.

```html
<h1 class="pl-page-title">Pilates near you</h1>
<p class="pl-body-medium-regular">Book a class in seconds.</p>
```

## Components

Open [index.html](index.html) and use the sidebar. The **Figma parity** section at the
bottom measures every component live and compares it against the dimension Figma
reports. If you change `components.css`, reload and make sure they still pass.
To read the results without a browser:

```
chrome --headless --allow-file-access-from-files --virtual-time-budget=6000 \
  --dump-dom file://$PWD/index.html | sed -n '/id="checks"/,/<\/tbody>/p'
```

Interactive states use real pseudo-classes, so Figma's Hovered / Pressed / Disabled
map to `:hover` / `:active` / `:disabled`. Each variant only sets custom properties;
the base rule consumes them.

### `.pl-btn` — PLButton (`1560:1318`)

```html
<button class="pl-btn pl-btn--md pl-btn--primary">Book class</button>

<button class="pl-btn pl-btn--lg pl-btn--primary pl-btn--pill pl-btn--full">
  <span class="pl-btn__icon" aria-hidden="true"><svg>…</svg></span>Reserve
</button>
```

| Group | Classes |
| --- | --- |
| Size | `--sm` (34px) · `--md` (48px) · `--lg` (56px) |
| Label | `--sm` → `buttonLabelSmall medium` (13/18) · `--md` / `--lg` → `buttonLabelLarge medium` (16/24) |
| Variant | `--primary` `--secondary` `--neutral` `--neutral-solid` `--outline` `--destructive` `--inverse` `--ghost` `--link` `--link-accent` |
| Radius | `--pill` (default is Figma's Regular, 16px) |
| Layout | `--full` (100% width) · `--edges` (label and icons pushed apart) |
| Slot | `.pl-btn__icon` — sized 16px on sm/md, 20px on lg |

`--link` is underlined at every size and in every state, including disabled;
`--link-accent` never is.
Both drop their padding and background — the box is just the text line.

### `.pl-icon-btn` — PLIconButton (`1589:977`)

Square: 36 / 44 / 52. The icon box is always 20px; padding produces the outer size.

```html
<button class="pl-icon-btn pl-icon-btn--md pl-icon-btn--raised" aria-label="Share">
  <svg>…</svg>
</button>
```

Sizes `--sm` `--md` `--lg`; variants `--primary` `--raised` `--ghost` `--neutral` `--inverse`.
`--raised` carries `--pl-elevation-sm`. **`aria-label` is required** — there's no visible text.

### `.pl-chip` — PLChip (`925:12624`)

One size, **42px** tall — 44 with a trailing icon, since the 20px icon slot is taller
than the 18px label line. The label is `bodySmall medium` (13/18). Selection is a
state, not a pseudo-class:

```html
<button class="pl-chip pl-chip--neutral pl-chip--filter" aria-pressed="true">Pilates</button>
```

```html
<button class="pl-chip pl-chip--neutral">Date
  <span class="pl-chip__icon"><svg class="pl-icon"><use href="#pl-chevron-down"></use></svg></span>
</button>
```

Styles `--neutral` `--neutral-solid` `--outline`; `--regular` for the square radius;
`--filter` for the tighter 4px gap that filter chips use. Dropdown chips take
`#pl-chevron-down` in the icon slot — that's the `chevron.down` glyph Figma uses. Selected via `.is-selected`
or `[aria-pressed="true"]`, and it looks identical across all three styles.

Figma's chip matrix is sparse — 36 variants, not the full 60. `Outline` only exists
for `Chip filter`, and `Chip toggle outline` only as Neutral Solid / Regular. The CSS
lets you combine anything, so some combinations have no Figma counterpart.

### `.pl-field` — Text field (`798:1537`) / Password field (`800:31`)

Form-page inputs. Five states each: **Placeholder**, **Disabled**, **Focused**, **Filled**, **Error**.
See the **Form** section in `index.html` for the full variant matrix.

```html
<div class="pl-field is-error">
  <span class="pl-field__box">
    <input class="pl-field__input" value="Value">
  </span>
  <span class="pl-field__error">Error</span>
</div>

<label class="pl-field pl-field--password">
  <span class="pl-field__box">
    <input class="pl-field__input" type="password" placeholder="Password">
    <button type="button" class="pl-field__icon" aria-label="Show password">
      <svg class="pl-icon" aria-hidden="true"><use href="#pl-eye-slash"></use></svg>
    </button>
  </span>
</label>
```

`.pl-field__box` is 52px tall (56px with `.pl-field--password`, whose 24px toggle sets
the floor). Focus is handled by `:focus-within`; add `.is-focused` for static demos,
`.is-error` or `.is-disabled` on `.pl-field`. The 2px focus/error stroke is always
present but transparent, so the box never resizes. Password visibility uses
`#pl-eye-slash` / `#pl-eye`.

### `.pl-search-bar` — Search bar (`1832:2160`)

```html
<div class="pl-search-bar">
  <span class="pl-search-bar__icon" aria-hidden="true">
    <svg class="pl-icon"><use href="#pl-search"></use></svg></span>
  <input class="pl-search-bar__input" placeholder="Label" aria-label="Search">
  <button class="pl-search-bar__clear pl-search-bar__icon" type="button" aria-label="Clear search">
    <svg class="pl-icon"><use href="#pl-close"></use></svg></button>
</div>
```

48px tall, `Radius/Semantic/xxl` (24px), `surface/default` on a 1px `border/default`
stroke — not `.pl-field`'s inset `surface/subtle` box. Both icons are Figma booleans:
**`Leading icon` defaults on, `Trailing icon` defaults off**, so the clear button is
only in the markup once there's a value to clear. Omit either `<span>`/`<button>`.

The placeholder/value split is a separate two-variant `Label` component in Figma
(`Active=False` → `text/secondary`, `Active=True` → `text/primary`); in CSS that's just
`::placeholder` versus the input colour. Focus uses `:focus-within` → `border/focus`.

Two things the Figma file gets wrong here, both worth fixing at the source:

- **The frame is FIXED 48 tall but binds 16px vertical padding**, which a 24px icon row
  can't fit inside (16 + 24 + 16 = 56). The height wins on canvas, so the CSS hard-codes
  the 12px that actually renders and only tokenises `padding-x`.
- **`Leading SF name` still reads `chevron.left`** while the glyph is `􀊫`
  (magnifyingglass) — the usual [hidden-name drift](#known-gaps-in-the-figma-source).
  The CSS follows the glyph and uses `#pl-search`.

Icon colour is `--pl-icon-default`, not the `button/icon/*` variables Figma binds: those
resolve to `#020203` in *both* modes, so a dark-mode search bar would get a black icon
on a dark surface.

### Cards — `.pl-card` + a per-card class

Class card, Schedule card, Pack, Map card and See all share one shell: `surface/default`,
16px radius, `card/padding-md`, and a **1px `border/default` outline** — every card
gained that border in the 2026-08-13 update. Selected swaps it for a 2px
`border/focus`; because Figma strokes are drawn *inside* the frame, the border is
absorbed into the padding so the card doesn't change size between states.

States are composable rather than one class per Figma variant, because Figma's six
states are really three independent things:

| Figma state | Classes |
| --- | --- |
| Default | `.pl-card .pl-class-card` |
| Selected | `+ .is-selected` (2px `border/focus`) |
| Unavailable / Sold out / Reserved / Booking window | `+ .is-dimmed` (text → `text/disabled`) |
| Sold out / Reserved | swap the price for `.pl-card__status--sold-out` / `--reserved` |
| Booking window | add `.pl-card__message` as the last child |

```html
<button class="pl-card pl-class-card">
  <span class="pl-class-card__body">
    <span class="pl-class-card__row">
      <span class="pl-class-card__time">12:00 PM</span>
      <span class="pl-class-card__duration">60 min</span>
    </span>
    <span class="pl-class-card__row">
      <span class="pl-class-card__instructor">Tricia D</span>
      <span class="pl-price"><span class="pl-price__amounts">
        <span class="pl-price__current">$25</span>
      </span></span>
    </span>
  </span>
</button>
```

**`.pl-schedule-card`** adds `__meta` (time · instructor), `__title`, optional
`__venue`, and a footer row with `__rating` and the price.

**`.pl-price`** (Schedule price, `1194:1153`) — `__amounts` wraps `__current` and
optional `__original`. Add `.pl-price--offer` to turn the current price green
(`text/price/discount`) and strike through the original. `.is-disabled`, or an
ancestor `.is-dimmed`, greys the whole thing.

### Re-exporting the icons

`icons/` holds one SVG per icon; `icons.js` is generated from them.

1. Export the node from Figma (`figma_execute` → `exportAsync({ format: 'SVG_STRING' })`).
   Most live in the `iOS icons` frame `2428:5548`; the tab icons are the components
   `1493:5` / `1493:4` / `1493:3` / `1493:2`.
2. Save it as `icons/<name>.svg`, and rewrite every painted colour to `currentColor`.
   **Stars are different:** `icons/star-fill.svg`, `star-half.svg`, and
   `star-outline.svg` are exact copies of the iOS star SVG exports — do not
   redraw, re-trace, or edit their path data or fills. If the source artwork
   changes, replace the file wholesale with the new export. `map-pin.svg` is
   the same: an exact copy of `assets/Map card pin.svg`. Do not redraw,
   re-trace, or edit its path data.
3. Add the name to `GROUPS` in `build-icons.mjs` — anything unlisted still ships, it
   just lands in an "Other" group.
4. `node design-system/build-icons.mjs`

Keep each SVG's own `viewBox`: SF Symbol outlines routinely overflow the 16/20/24 frame
they sit in, and those bounds are what make the artwork centre inside a square slot.

## Regenerating after Figma changes

1. Open the Playlist Design System file in Figma Desktop with the Figma Console MCP
   Desktop Bridge plugin running.
2. Export the raw CSS — via the MCP tool `figma_export_tokens`:
   `format: css-vars`, `scope: file`, `modes: all`, `colorFormat: hex`,
   `sizeUnit: px`, `prefix: pl-`, `resolveAliases: true`, `strategy: replace`,
   written to `design-system/tokens.raw.css`.
   (The tool writes into a *directory* named after `outputPath` — move the inner
   file up one level.)
3. `node design-system/postprocess-tokens.mjs`
4. `node design-system/build-typography.mjs`
5. Open `index.html` and eyeball it — the Figma parity table must stay green.

### The exporter lies about changed aliases

`figma_export_tokens` caches a variable's alias target and keeps emitting the **old**
one after it changes in Figma. Re-exporting doesn't clear it, and neither does
`figma_get_variables({refreshCache: true})` — but the Plugin API reports the new value
correctly, so the file is fine and the exporter is wrong.

This bit us on `label/sm/*`: Figma moved it from 12/16 to 13/18, and the export kept
saying 12/16. `postprocess-tokens.mjs` therefore carries a `CORRECTIONS` list that
re-declares the affected tokens after the generated block. It prints how many
corrections it applied, and tells you when one has become redundant so you can delete it.

**After any Figma change, verify rather than trust the export.** Dump the authoritative
values with `figma_execute` (walk `valuesByMode`, following `VARIABLE_ALIAS` hops) and
diff them against the resolved `tokens.css`. That is how the 3 stale styles were found —
everything else matched.

`build-typography.mjs` holds the role-style → token-style mapping, transcribed from
Figma along with the size/lineHeight/weight Figma reports. It **asserts those still
match** the resolved tokens and exits non-zero if they don't, so a variable change in
Figma that breaks a text style fails the build instead of silently emitting wrong CSS.
If text styles are *added or renamed* in Figma, re-dump them with the
`figma_get_text_styles` MCP tool and update the table by hand.

## What the post-processor fixes

The raw export isn't directly usable. `postprocess-tokens.mjs` handles four things:

1. **Selectors.** Single-mode collections export under `[data-theme="mode"]` /
   `[data-theme="mode-1"]`, which never match anything → rewritten to `:root`.
2. **Dark mode.** Exports as `.dark` → rewritten to `[data-theme="dark"], .dark`.
3. **Float noise.** `0.1599999964237213` → `0.16`.
4. **Font weights.** Figma stores these as style *names* (`SemiBold`), which is not
   a valid CSS `font-weight`. The primitives are overridden with numbers (400–900)
   in a trailing `:root` block, so all 37 semantic type styles resolve correctly.
   Font families also get a real fallback stack there.

It also composes `--pl-elevation-*` from the decomposed `--pl-shadow-{size}-{x,y,blur,spread,opacity}`
tokens, since Figma can't express a `box-shadow` shorthand as a variable.

## Known gaps in the Figma source

Flagging these because they'll bite in code, and they're design-side fixes:

- **`surface/inset` is invisible in dark mode** — it resolves to `neutral/900`,
  the same value as `bg/default`, so an inset surface disappears against the
  default background.
- **`--pl-shadow-rgb` is hardcoded** to `2 2 3` in the post-processor. That's the
  value of `shadow/default` (neutral/900), which is currently identical in light
  and dark. If the Figma shadow color ever diverges by mode, this needs revisiting —
  CSS can't split a hex variable into channels.
- **Only `Color/Semantic` has a dark mode.** Every other collection is single-mode,
  which is correct, but it means nothing else responds to `data-theme`.
- **`role/button label/*` and `role/input label/*` are duplicates.** Both pairs resolve
  to exactly `label-lg`/`label-md` medium and semibold — 8 Figma text styles covering
  4 distinct sets of metrics. Harmless, but they can't be told apart in code.
- **`role/screenTitle` was deleted** (it was 40/48, mapping to `display-lg`). `.pl-screen-title`
  is gone with it — use `.pl-text-display-lg` if you need those metrics.
- **`label/sm/*` changed meaning.** It used to be a single 12/16 style; it is now
  `label/sm/{regular,medium,semibold}` at **13/18**. `role/tabLabel` (still 12/16) therefore
  no longer maps to it and now points at `caption-lg`. Anything that was using
  `.pl-text-label-sm` needs to move to `.pl-text-caption-lg` (12/16) or
  `.pl-text-label-sm-regular` (13/18) depending on which it meant.

Found while building the components:

- **The Search bar can't fit its own padding.** The frame is FIXED at 48 tall but binds
  `space/md` (16) top and bottom around a 24px icon row — 56px of content in a 48px box.
  Either the height or the padding binding is wrong.
- **Search bar `Leading SF name` says `chevron.left`** while the glyph is `􀊫`
  (magnifyingglass) — an unfilled hidden-name default, the same drift the icon buttons
  hit. The name and the glyph are separate fields; setting one doesn't update the other.
- **The Search bar's icons bind `button/icon/{neutral,raised}/fg/default`**, which resolve
  to `#020203` in *both* modes — they're not theme-aware, so a dark-mode search bar would
  render a black icon on a dark surface. `icon/default` is the token that already handles
  this. (`button/icon/neutral/*` is also a *remote* library variable, so it never reaches
  the token export.)
- **PLButton Destructive has no hover.** Its `Hovered` variant is bound to
  `button/destructive/bg/default` — visually identical to rest. The
  `button/destructive/bg/hovered` token exists but nothing uses it. `components.css`
  wires the hover token up so the state isn't dead; swap it back to match Figma exactly.
- **PLButton Destructive Disabled keeps `fg/default`**, so the label doesn't dim.
  `button/destructive/fg/disabled` exists and is unused.
- **PLButton Ghost's border points at a variable that isn't in this file** —
  `button/label/ghost/border/default` (`VariableID:788:2483`) resolves by ID but isn't a
  local variable, so it's absent from the token export. It renders fully transparent, so
  `components.css` uses a transparent border purely to keep the box from resizing.
